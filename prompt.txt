PROJECT CONTEXT

This is a console (terminal) Restaurant Management System. The main focus is the restaurant staff and their payroll: who works in the restaurant, what each person does, and how each person is paid. Around that, there is a simple menu, orders and billing.

Staff roles and what they do:
- Manager: runs the restaurant. Hires, fires, promotes and updates staff, approves leave, runs payroll, manages the menu, sees reports. Pay = base salary + fixed allowance.
- Chef: cooks orders, sees the cooking queue, marks orders as Cooking or Ready. Pay = base salary + a rate per dish cooked.
- Waiter: takes orders at tables, serves food, receives tips. Pay = base salary + tips.
- Cashier: creates bills, takes payment, closes orders. Pay = base salary + overtime pay.
- Cleaner: cleans tables and kitchen, has a cleaning schedule. Pay = based on days present.
- Head Chef: a person who is both a Chef and a Manager (cooks and also manages the kitchen). This is the diamond problem case. Pay combines both parts.

Payroll: each staff member has attendance data (days present, overtime hours). A payroll run calculates gross pay from the role's pay rule, subtracts a simple PF percentage and a simple tax slab, and produces a payslip. Payslips are shown on screen and kept in a history.

Menu and orders: the menu has dishes with name, price and stock. A waiter places an order for a table, stock reduces when an order is placed (out of stock gives an error), the order moves through the states Placed, Cooking, Ready, Served and Paid. The cashier makes a bill with GST, optional discount and tip. The tip goes to the waiter's pay data.

Access control: a user logs in with their staff ID, and the role decides which menu they see. Manager can do everything. Cashier does billing. Waiter takes orders and sees own tips. Chef sees and updates the cooking queue. Cleaner sees own schedule.

Data storage: staff and menu data must be saved in files and loaded again when the program starts, so the user can add, view, update and delete records from the terminal and the data survives restarts. On the first run, create one default manager so someone can log in.
